# hooks/ — 거버넌스 엔진 상세

> 루트 `CLAUDE.md` 에서 원문 그대로 분리했다(20261112). 하위 디렉터리의 CLAUDE.md 는 그 폴더의 파일을 읽거나 고칠 때만 로드된다 — 루트에는 요약과 포인터만 있다.

### 거버넌스 엔진

거버넌스 훅 이벤트 4종(+ `Notification` → `notify.sh` 보조 1종)이 자동 실행되며, `hooks/rules.jsonl`에 정의된 6개 규칙 중 R-1~R-5 를 검사한다 (R-6 은 `enabled: false` — gbrain-ko manual-only 설계):

- `SessionStart` → `session-start.sh`: 메타 스킬 주입 + session-progress rehydrate. **조립 순서 계약**: `specops-ko-anchor` → `freecomment-pending` → `session-progress-reconcile` → `batch-resume`(조건부 — ACTIVE 마커 있는 미완 batch 존재 시) → 메타 본문 → `session-progress-rehydrate` — harness 는 훅 출력 1건이 **문자 10,000**(UTF-16 단위 — JS length, 바이트·코드포인트 아님)을 넘으면 파일로 빼고 선두 2KB 프리뷰만 인라인하므로 행동 지시 블록을 앞에 두고, 총량은 **예산 9,500자 가드**(넘치면 rehydrate 만 절단 + 생략 포인터)로 한도 아래에 둔다 (`scripts/tests/test-session-start-order.sh` 가 잠금)
- `PreToolUse` → `pretool-governance.sh` (v1.14.0 신설): R-1(commit 전 verify)·R-2(PR 전 verify) **사전 차단(Hard block)** — verify 누락 시 `git commit`·`gh pr create` 실행 전 deny. **관할 한정**: cwd 에 `.specops/` 부재 시(specops 미사용 repo) 면제 — 플러그인은 자기 관할 repo 만 통제(5원칙 4 주권). 면제 **4종**: `SPECOPS_GOVERNANCE_BYPASS=1`(인라인 사용 시 `SPECOPS_BYPASS_REASON='<사유>'` 병기 필수 — 무사유는 deny) · docs/design-only 변경(`*.md`·`*.txt`·`*.rst` + `screens/*.html`·`.specops/*`) · `.specops/` 부재 · fail-open(transcript 부재·tool_use 이벤트 0건(rc=2)·rules·jq 판정 불가)

> **플러그인 런타임 예외** (`_files_all_docs`): `.claude-plugin/plugin.json` 이 있는 repo 에서는 `skills/**/*.md`(SKILL.md 와 보조 md 전부 — 11회차 E-1)·`commands/*.md`·`agents/*.md`·`templates/*.md`·`hooks/*`·`.claude-plugin/*` 이 **확장자와 무관하게 코드**다. 루트 `README`·`CHANGELOG`·`CLAUDE.md` 는 면제 유지(배포 런타임 아님). 모든 repo 에서 `requirements*.txt`·`constraints*.txt`·`CMakeLists.txt`·`requirements/`·`constraints/` 아래 txt 는 코드다(의존성·빌드 목록 — 11회차 E-6). (근거·이력: docs/governance-history.md §1)
- `PostToolUse` → `posttool-governance.sh`: R-1(commit 전 verify), R-2(PR 전 verify) **감사 기록(Soft Warn)**, R-3(스킬 선언 투명성). 기록 시 `_audit_scope_class` 로 **방금 액션의 커밋 범위**(R-1 `HEAD~1..HEAD` · R-2 `base...HEAD`)를 분류해 `scope_class` 필드를 남긴다 — 면제 시엔 기록 자체가 없으므로 posttool 기여분에 `docs-only` 는 구조적으로 나타나지 않고 `code`·`empty`·판정불가(필드 부재)만 쌓인다. matcher 는 `Bash|Skill` 이다(모든 posttool 규칙의 `trigger_tool` 집합 — `test-manifest.sh` T12.h·T12.i 가 잠금). Bash 는 R-1/R-2 `trigger_pattern` 사전 필터(pretool 동형)로 커밋·PR 이 아닌 명령을 git 호출 전에 끝낸다 — **판정 불가(정규식 로드 실패·정규식 오류)면 조기 종료하지 않고 종전 경로**로 간다(감사층은 기록 보존이 안전 · `test-hooks.sh` T8.h~T8.k).
- `Stop` → 3 훅 발화: `ensure-session-progress.sh`(session-progress.md 보장 — `.specops/` 가 없으면 아무것도 만들지 않는다) + `stop-governance.sh`(거버넌스: R-4 성공 주장 + 테스트 미실행, R-5 plan 수정 + Advisor 협의 누락(협의를 **주장**하면 transcript 실호출 증거 요구 — `server_tool_use`(advisor)↔`advisor_tool_result` 또는 `critic-ask.sh`. `해당 없음` 정직 선언은 증거 불요), R-6 `/verify` + evidence.md 후 gbrain-append 호출 부재 — 비활성) + `freecomment-capture.sh`(자유 코멘트 자동 캡처 — pending 적재, SessionStart 에서 LLM 요약→freelog.md · `.specops/config.yaml` 의 `hooks.freecomment-capture.enabled: false` 나 프로파일 `standard`·`minimal` 로 끈다)

**관할 한정은 pretool 만의 것이 아니다** — 기록을 남기는 나머지 훅(`posttool-governance`·`stop-governance`·`freecomment-capture`·`ensure-session-progress`)도 `.specops/` 가 없는 repo 에서는 판정·기록·생성을 하지 않는다. 훅이 `.specops/` 를 만들면 그 repo 가 관할로 편입돼 다음 커밋부터 R-1 이 막는다(실측 20261009: 플러그인을 쓰지 않는 repo 4곳에 흔적). 디렉토리는 관할을 여는 쪽(`/init-project` · specifying-ko 의 FID 생성 · `session-progress-append.sh`)만 만든다. 셸이 같은 저장소의 다른 worktree 에 있으면 R-1·R-2·감사는 그 worktree 의 git 상태로 판정하고 `.specops` 는 셸이 자기 기록을 가진 worktree(그 FID 의 git 추적 안 된 기록이 있음 · session-progress.md 가 git 추적이면 제외)에 있으면 그 worktree 것을, 아니면 프로젝트 폴더 것을 읽는다(`_gov_apply_git_target` · `_gov_apply_record_root`). 단 그 worktree 의 브랜치가 `feat/batch-…` 이고 현재 폴더에 같은 이름의 배치 마커(`.specops/batch-…/ACTIVE`)가 있으면 옮기지 않는다.

R-1/R-2 는 **pretool=강제 차단 / posttool=감사** 로 역할이 분리된다(면제·fail-open 시 posttool audit trail 보존). 그 외 위반은 `.specops/<FID>/friction-log.jsonl`에 Soft Warn으로 기록된다.

> **면제 조회 — "이 커밋은 면제됩니까"를 미리 묻는다**: `bash scripts/_internal/scope-explain.sh '<커밋 명령>'`(인자, 또는 stdin 파이프)이 훅과 **같은 판정 함수**를 불러 `SCOPE=staged|conservative EXEMPT=yes|no REASON=<class>(<N> files)` 1줄로 답한다. rc 계약: **0=판정 성공 · 2=입력 없음/읽기 불가 · 3=판정기 로드 불가** — 판정 불가를 그럴듯한 1줄로 위장하지 않는다. 훅 경로에서 묻고 싶으면 `SPECOPS_DRYRUN=1`(env 또는 **명령 선두 인라인**)을 붙인다: 같은 1줄을 stderr 로 내고 **deny 한다** — 조회이므로 커밋을 실행하지 않는다(allow 를 한 건도 늘리지 않는 deny 전용 경로). 커밋 명령 **앞의** `cd <repo 내부 경로>`·bare `VAR=값` 선행 줄은 **최대 8줄까지** 안전 prelude 로 인정해 그 뒤 커밋을 판정한다(그 밖의 선행 줄 — `cd ..`·`cd -`·타 repo 절대경로·명령치환·`git add -A` 등 — 은 보수 판정). 명령이 다른 작업 트리로 옮겨(`cd`·`-C`·`GIT_DIR=`) 커밋하면 문서 면제를 주지 않는다 — 같은 작업 트리일 때만 면제. ⚠️ **DRYRUN 의 관할 경계**: `.specops/` 부재 repo 와 **사유를 병기한** `SPECOPS_GOVERNANCE_BYPASS=1`(무사유는 deny 라 실행되지 않는다) 사용 시에는 훅이 **그 앞 분기에서 이미 빠져나가** DRYRUN 이 무시되고 커밋이 **실제로 실행된다**(실측: 두 경우 모두 `{"continue":true}`) — 조회 의도였다면 커밋이 나간 뒤에야 알게 되므로, 그 두 상황에서는 `scope-explain.sh` 를 쓴다. (근거·이력: docs/governance-history.md §2)

**실행-근거 gate** (v1.45.0, `governance-lib.sh:_verify_exec_evidence`): R-1/R-2 의 verify 면제는 **자기보고만으로 열리지 않는다**. transcript 가용 시, 자기보고 면제 3경로 — session-progress 의 `/verify PASS` 줄 · evidence.md 의 `RUN-VERIFICATION-RESULT` 스탬프 · `verifying-evidence-ko` Skill 호출 — 는 **무엇이 있든** transcript 의 `tool_use` ↔ `tool_result` 를 `tool_use_id` 로 join 해 검증 러너가 **실제로 실행되어 `VERIFY: PASS` 를 출력했는지** 확인한 뒤에만 면제된다 (`VERIFY: PARTIAL`·`FAIL`·`is_error` 는 불인정). 모델이 spec.md 에 스스로 쓰는 `§auto: true` 라벨의 **무조건 면제는 제거됐다** — 자기발급 면제표였기 때문이다. 무인 모드(`/start-all-auto`)도 chain 에 verify 가 있어 실제 실행하므로 정직한 흐름은 그대로 통과한다. 판정 불가(transcript 부재·tool_use 이벤트 0건(rc=2)·jq 실패)는 fail-open. 이 저장소의 `tests/run-related.sh` 도 러너로 읽는다(덮은 통과에만 `VERIFY: PASS` — 20261113-commit-gate-related-evidence).

> **실행 증거는 그 FID 의 것이어야 하고, 검증 뒤 코드가 바뀌면 닫힌다** (20261009): 러너 명령에 FID 가 글자로 적혀 있는데(`run-verification.sh <FID>`) 그것이 활성 FID 가 아니면 실행 증거로 치지 않는다 — 한 세션에서 FID 여럿을 다루면 앞 FID 의 PASS 가 뒤 FID 의 커밋을 열었다(실기록 커밋 919건 중 12건). FID 가 변수거나 `run-all.sh` 면 판단하지 않는다. 그리고 판정 SoT(`verification-state.sh current`)가 `STALE` 이면 진행 기록·스탬프가 있어도 R-1 은 열리지 않는다 — 종전에는 transcript 의 Edit/Write 이벤트로만 무효화를 봐서, 셸 명령·포매터·코드 생성기·서브에이전트가 고친 코드는 검증 없이 커밋됐다. `STALE` 이어도 막지 않는 경우는 셋이다(`_vs_stale_blocks`) — 전체 스위트가 **지금 이 트리**에서 통과했거나(`full-suite-fresh.sh` rc 0 — `run-all.sh` 는 판정 상태를 갱신하지 않는다), **관련 스위트가 지금 트리에서 변경이 닿는 스위트를 전부 덮어 통과했거나**(`related-suite-fresh.sh` rc 0 — 통과 기록 `.specops/.related-suite-pass` 가 있을 때만 판정 · 20261113), 달라진 것이 추적하지 않는 파일뿐일 때(`verification-state.sh stale-scope` = `untracked-only` — 기록의 `tracked_nondoc_hash` 와 대조 · 커밋만 실행하는 명령(`git commit [-a] -m …` 한 줄 — `_commit_scope_is_staged`)일 때만 · compound·파이프·경로 인자는 조회용 명령과 함께여도 제외). (근거·이력: docs/governance-history.md §3)

> 트리거(`hooks/rules.jsonl` R-1·R-2 `trigger_pattern`)는 명령 위치의 `git commit`·`gh pr create` 를 env 접두·래퍼(`rtk`·`time`·`nice`·`sudo`·`env` 와 그 옵션 · `exec`·`nohup`·`timeout N`)·제어 키워드(`then`·`do`·`else`·`if`·`while`·`!`)·`case` 가지 뒤, 경로로 부른 형태(`/usr/bin/git`), 줄 연속, `gh pr -R … create` 까지 인식한다. `sh -c`·`eval`·`xargs`·alias·변수에 든 명령은 여전히 범위 밖이다(`docs/architecture.md` §6-1 표). pretool 을 설정으로 끈 채 커밋·PR 이 나가면 repo 레벨 friction-log 에 `GOVERNANCE-DISABLED` 가 남는다(끄는 것 자체는 막지 않는다). (근거·이력: docs/governance-history.md §4)

> 실행 증거(`_exec_rc ≠ 1` — `0`=러너 실행 확인 · `2`=판정 불가 fail-open)는 자기보고 3경로를 **여는 전제조건**이지 단독 면제가 아니다. 앵커가 하나도 없으면 러너를 몇 번 돌려도 통과하지 않는다. R-1 의 implement 창은 FID 에 `tasks.md` 가 있고 **verify 가 아직 유효 PASS 가 아닐 때**(`verification-state` 가 `NOT_RUN`·`PARTIAL`·`FAIL`) 열리며 receipt 로 면제된다 — 종전의 `evidence.md 부재` 조건은 구현 중 태스크가 그 파일을 쓰면 남은 태스크의 탈출구를 닫았다. `STALE`·`WAIVED` 는 창이 닫힌다. deny 메시지는 세 조건(①·②·receipt)의 **실제 상태**를 표시한다(`cause` 진단이 없거나 파싱 실패면 종전 무조건 3블록 문안으로 떨어지고 deny 는 유지된다). (근거·이력: docs/governance-history.md §5)

> **quick 경로** (20261010): 태스크 문서는 있고 명세(`spec.md`)가 없는 FID 는 `/quick-fix` 의 FID 다. R-1 의 receipt 경로가 그대로 쓰이되(테스트 실제 실행 · staged ⊆ outputs · 트리 신선도), `check-task-receipt.sh` 가 판정기(`scripts/_internal/quick-scope.sh`)를 불러 **범위**(구현 파일 수 · 변경 줄 수 상한 — 테스트·문서 제외 · 고위험 신호 없음. 수치는 판정기 머리의 상수가 유일한 정의다)와 **리뷰**(통과 판정의 `reviews/T1-C-report.md` 가 마지막 수정보다 새것)를 함께 요구한다. 넘으면 deny 하고 `/maintain` 을 안내한다(`cause.receipt = quick-over | quick-noreview`). quick 구조의 FID 는 **verify 상태와 무관하게** 이 판정을 받는다 — 검증 러너가 PASS 를 내도 영수증 가지를 타고(`_quick_structure`), 스테이징된 것만 커밋하는 명령이 아니면(`-a`·경로 인자·다른 명령과 묶음) 막는다(`cause.receipt = quick-unstaged`).  판정기가 판정하지 못하면(판정 불가 — 따옴표가 든 파일 이름 포함) 막되 범위 초과라고 말하지 않는다. (근거·이력: docs/governance-history.md §6)

### `hooks/governance-lib.sh` 는 800줄 규칙 예외다

`~/.claude/rules/coding-style.md` 는 "파일 800줄 max" 를 언어 한정 없이 적는다. 이 repo 는 그 규칙을 **`hooks/governance-lib.sh` 한 파일에 한해 적용하지 않는다** — 이 파일의 함수들이 하나의 판정 계약(transcript 조인 · 면제 클래스 · 마찰 기록 · 우회 분류 · degraded 기록)을 공유하는 bash 라이브러리라 응집도가 곧 목적이고, 인터페이스는 훅이 source 해서 함수를 부르는 단일 표면이다. 나눌 이유가 생기면 **되돌려-관찰(변이 주입)로 각 가드의 생존을 실증하며** 나눈다. 이 예외는 분할 검토를 영구 금지하지 않고 근거 없는 분할만 막는다. 예외는 이 **한 파일에만** 적용되며 다른 파일의 비대화를 정당화하지 않는다. (근거·이력: docs/governance-history.md §7)

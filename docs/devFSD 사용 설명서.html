devFSD — 한마디로 출발하는 개발 자율주행

만들고 싶은 기능을 한 줄로 말하면, 설계부터 구현·테스트·PR 생성까지 차례로 진행합니다. 사람은 설계를 승인하고 마지막에 병합만 합니다.

1구간

출발부터 도착까지

차가 정류장을 차례로 지나갑니다. 빨간 차단기 두 곳에서만 멈추고, 그곳에서는 사람이 확인합니다. 정류장을 누르면 그 단계 설명을 볼 수 있습니다.

출발만들고 싶은 것을 한 줄로 입력합니다.
  1. 출발만들고 싶은 것을 한 줄로 입력합니다.
  2. 명세무엇을 만들지와 완료 기준을 문서로 정리합니다.
  3. 명확화애매한 점을 묶어서 묻습니다. 최대 2번입니다.
  4. 승인설계 전체를 한 번에 보고 승인합니다.
  5. 계획구현 방법을 짜고, 분야 전문가가 한 번 더 봅니다.
  6. 분해일을 작은 작업 단위로 나눕니다.
  7. 구현테스트를 먼저 쓰고 코드를 만든 뒤 리뷰합니다.
  8. 검증테스트를 실제로 돌려 통과 기록을 남깁니다.
  9. 보안·통합·성능해당하는 변경일 때만 점검합니다.
  10. PR만든 결과를 보여 주고 PR을 만듭니다.
  11. 머지PR을 확인하고 병합합니다.

작은 작업은 더 짧은 길로 갑니다. 인증·DB 구조·데이터 삭제 같은 위험 신호가 없으면 명세 1장 → 구현 → 리뷰 → 검증 → PR 순서의 기본 경로를 자동으로 고릅니다.

2구간

준비물

Claude Code가 설치돼 있어야 합니다. macOS와 Linux에서 검증했고, Windows는 WSL에서 사용합니다.

도구필요한가없으면 생기는 일
git필수진행 자체가 되지 않습니다.
jq필수안전장치가 오류 없이 꺼집니다. 꼭 설치하세요.
python3 + pyyaml권장작업 분해 검사 일부를 건너뜁니다.
gh선택PR 만들기만 직접 해야 합니다.
brew install jq gh

위 명령은 macOS(Homebrew) 기준입니다. Ubuntu는 sudo apt install jq gh 입니다.

3구간

설치

  1. 플러그인 저장소를 등록합니다

    claude plugin marketplace add andyko18/devFSD

    터미널에서 실행합니다.

  2. 플러그인을 설치합니다

    claude plugin install devfsd@devfsd

  3. Claude Code를 다시 시작합니다

    다시 시작해야 플러그인이 적용됩니다.

  4. 설치를 확인합니다

    Claude Code 대화창에 아래처럼 말로 입력합니다. 준비물이 빠졌으면 여기서 알려 줍니다.

    devfsd doctor 돌려줘
4구간

첫 실행 따라 하기

작업할 프로젝트 폴더에서 Claude Code를 열고 한 줄만 입력합니다. 슬래시 명령 대신 "CSV 줄 수 세기 CLI 만들어줘"처럼 말로 해도 됩니다.

/start "CSV 줄 수 세기 CLI 만들어줘"
나 ▸ /start "CSV 줄 수 세기 CLI 만들어줘"
devFSD 가벼운 작업으로 판정 — 기본 경로로 진행합니다
devFSD 질문: 빈 줄도 셀까요? (추천: 세지 않는다)
나 ▸ 추천대로
devFSD 명세 1장을 작성했습니다. 승인할까요?
나 ▸ 승인
devFSD 구현 → 리뷰 → 검증 … VERIFY: PASS
devFSD PR을 만들었습니다. 확인 후 병합하세요.
이해를 돕는 예시 화면입니다. 실제 문구와 질문은 작업마다 다릅니다.

내가 할 일은 세 가지입니다. 질문에 답하기, 설계 승인하기, 마지막에 PR 병합하기. 승인한 뒤에는 PR이 만들어질 때까지 묻지 않고 진행합니다.

5구간

어떤 명령을 쓸까

지금 상황을 고르면 쓸 명령을 알려 드립니다.

/init-project 프로젝트이름

처음 한 번만 실행합니다. 몇 가지 질문에 답하면 프로젝트 기본 문서를 만들어 줍니다. 그다음부터는 기능마다 /start 를 씁니다.

명령언제 쓰나
/init-project프로젝트를 처음 준비할 때 한 번
/start새 기능 하나를 만들 때
/maintain이미 있는 코드를 고치거나 버그를 잡을 때
/quick-fix몇 줄짜리 수정. 문서 없이 테스트와 리뷰 1회만 합니다
/start-foundation로그인·화면 틀 같은 공통 부분을 먼저 만들 때 한 번
/start-all요구사항 문서의 기능 전체를 한꺼번에 구현할 때
/status지금 어느 단계인지 볼 때
/feedback쓰다 겪은 불편을 알릴 때

/status 가 Claude Code 기본 명령과 겹치면 /devfsd:status 로 입력합니다.

6구간

안전장치 — 증거가 없으면 멈춥니다

테스트를 실제로 돌려 통과한 기록이 없으면 커밋과 PR 생성이 실행되기 전에 막힙니다. "다 됐다"는 말로는 열리지 않습니다. 아래에서 직접 눌러 보세요.

git commit저장소
버튼을 눌러 차단기가 어떻게 움직이는지 확인하세요.

이 차단은 devFSD를 쓰는 폴더(.specops/ 가 있는 저장소)에서만 동작합니다. 다른 프로젝트의 커밋에는 관여하지 않습니다.

7구간

결과물은 어디에 남나

단계마다 만든 문서가 프로젝트의 .specops/ 폴더에 저장됩니다. 대화가 끊겨도 이 파일을 읽고 이어서 진행합니다.

.specops/
├── session-progress.md        어디까지 했는지 (이어 하기용)
└── 20261120-csv-line-count/   작업 하나 = 폴더 하나 (날짜-이름)
    ├── intent.md              무엇을 왜 만드는지
    ├── spec.md                명세
    ├── acceptance-criteria.md 완료 기준
    ├── plan.md · tasks.md     계획과 작업 목록
    └── evidence.md            테스트 통과 기록

코드는 feat/작업이름 브랜치에 커밋됩니다. 화면이 있는 기능이면 screens/ 폴더에 화면 설계와 미리보기도 생깁니다.

8구간

말로 요청하는 기능

/ 메뉴에는 자주 쓰는 명령만 있습니다. 아래 기능은 대화창에 말로 입력합니다.

이렇게 말한다하는 일
"devfsd doctor 돌려줘"설치와 환경을 점검합니다
"브레인스토밍 하자"만들기 전에 아이디어를 먼저 다듬습니다
"보안 스캔 돌려줘"코드의 보안 문제를 찾습니다
"아키텍처 개선점 분석해줘"나누거나 합칠 코드를 제안합니다
"기본 경로로 진행해줘"짧은 길을 직접 지정합니다
"이 인사이트 기록해줘"작업 중 알게 된 것을 남깁니다
9구간

막혔을 때

커밋이 "verify 누락"으로 막혔어요
정상 동작입니다. 검증(테스트 실행)이 통과하면 풀립니다. 진행 중이라면 그대로 두면 검증 단계가 실행됩니다.
어디까지 했는지 모르겠어요
/status 를 입력하세요. 새 대화를 열어도 이전 진행을 읽고 이어 갑니다.
얼마나 걸리나요
작은 작업은 짧은 길로 가고, 전 단계를 거치는 작업 1건은 중앙값 약 2시간으로 측정됐습니다(속도 개선 전 측정). 단계마다 별도 작업자를 띄우므로 그냥 시키는 것보다 사용량이 더 듭니다.
단계마다 확인하고 싶어요
/start --step "기능 설명" 처럼 --step 을 붙입니다. 무조건 전 단계를 거치려면 --full 입니다.
작업 하나를 끝냈어요. 다음 작업은요
새 대화에서 시작하세요. 대화가 길어질수록 느려지고 사용량이 늘어납니다.
업데이트하거나 끄고 싶어요
업데이트는 claude plugin update devfsd@devfsd 후 재시작, 잠시 끄기는 claude plugin disable devfsd, 삭제는 claude plugin uninstall devfsd 입니다.
발표 자료나 기획서도 되나요
맞지 않습니다. 테스트할 코드가 있는 작업에 쓰는 도구입니다.

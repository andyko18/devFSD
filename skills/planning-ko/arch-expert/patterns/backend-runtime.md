# 백엔드 런타임(재시도·타임아웃) 규칙 — arch-designer-ko 보조 파일

`backend-architecture.md` 가 있으면 항상 읽는다. plan 에 외부 호출(HTTP·DB 원격·메시지 브로커·서드파티 API)이 새로 생길 때만 대조한다.

- 재시도는 일시적 오류에만 한다(네트워크 타임아웃·연결 끊김·HTTP 429·503 등). 인증 실패·잘못된 요청(429 를 뺀 4xx)·타입 오류 같은 버그는 재시도하지 않는다 — 재시도 대상 오류 목록을 plan 에 적게 한다.
- 재시도 간격은 지수 백오프에 지터(무작위 흔들림)를 더한다 — 동시에 실패한 클라이언트들이 같은 순간에 다시 몰리지 않게 한다.
- 재시도에는 횟수 상한과 총 시간 상한을 둘 다 둔다.
- 모든 네트워크 호출에 타임아웃을 둔다. 라이브러리 기본값(무한 대기 포함)에 기대는 plan 은 지적한다.
- 재시도마다 로그를 남긴다 — 조용한 재시도는 체계적 장애를 가린다.
- 재시도·타임아웃 정책은 업무 로직과 분리된 한 곳(데코레이터·미들웨어·클라이언트 래퍼)에 두고, 그 클라이언트는 주입받아 테스트에서 바꿀 수 있게 한다.
- 핵심이 아닌 경로는 실패 시 캐시·기본값으로 물러설 수 있는지 plan 에 적는다(물러서면 안 되는 경로는 그렇다고 적는다).

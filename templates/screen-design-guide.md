# 화면 디자인 지침 — 목업을 쓰기 전에·쓴 뒤에

<!-- 참조: anthropics/claude-plugins-official frontend-design (Apache-2.0) 의 구조(먼저 결정 → 만들고 → 찍어 보고 빼기)를 업무 화면용으로 한국어 재작성. 문장 복제 없음 · 수치 원칙(대비·터치·간격·모션)은 일반 접근성 기준 -->

`screens/<name>.html` 을 만들거나 고칠 때 이 순서를 따른다: **① 브리프 5줄 → ② `templates/screen.html` 부품으로 작성 → ③ 찍고 보고 1~2회 다듬기.** 업무 화면은 마케팅 페이지가 아니다 — 개성은 **한 곳**에만 두고 나머지는 위계·밀도·일관성으로 만든다.

## ① 브리프 5줄 (작성 전에 먼저 쓴다 — 화면 md 의 `## 디자인 브리프` 절)

1. **주제·사용자·핵심 임무** — 누가 무엇을 하려고 이 화면을 여는가 (예: "창고 담당자가 오늘 부족 재고를 찾아 발주한다")
2. **원형과 밀도** — 목록·상세·폼·대시보드 중 무엇이고 행 높이는 얼마인가 (DESIGN.md D 다이얼: 높음 32px · 중간 40px · 낮음 48px)
3. **눈이 가장 먼저 갈 한 곳** — 주 액션 또는 핵심 수치 하나 (예: "부족 수량 KPI + 발주 버튼")
4. **쓸 부품** — `templates/screen.html` 클래스 이름으로 (예: `app-shell · page-header · kpi · table · badge · toolbar`)
5. **이번에 피할 기본값 1개** — 아래 금지 목록에서 이 화면이 빠지기 쉬운 것 (예: "목록을 카드 그리드로 그리기")

## ② 작성 규칙

**긍정 지침**
- 서체는 한글 1종 + 숫자·코드 보조 최대 1종. 타입 스케일은 5단 이하로 쓴다(`--text-*` 토큰만).
- 간격은 4/8 배수(`--space-*` 토큰만). 같은 관계의 요소는 같은 간격.
- 본문 줄 길이는 한글 40~45자 안팎에서 끊는다(넓은 화면에서 문단을 전폭으로 늘이지 않는다).
- 표의 숫자는 우측 정렬 + 고정폭 숫자(`.num`). 목록은 카드 반복이 아니라 표로.
- 강조색은 화면당 한 곳(주 액션·선택 상태). 상태는 배지로 **색 + 글자**를 함께.
- 테두리·구분선·번호·배지는 정보일 때만 쓴다. 순서가 없는 내용에 01/02/03 을 붙이지 않는다.
- 카피: 버튼은 동사("저장"·"발주"), 오류는 원인 + 해결("수량은 1 이상이어야 합니다"), 빈 화면은 다음 행동 1개를 권한다.
- 바닥선: 키보드 포커스가 보인다(`:focus-visible`) · 좁은 화면(390)에서 가로 스크롤 없음(표는 `.table-wrap` 안에서만) · 대비 4.5:1 · 터치 높이 40~44px · 움직임 줄이기 설정 존중.

**금지 목록 — 흔한 "AI 화면" 기본값**
- 보라·분홍 그라디언트 장식, 보라 강조색을 기본으로 쓰기 (업무·금융·공공 화면에서 특히)
- 같은 둥근 카드·같은 그림자를 끝없이 반복하는 "SaaS 카드 키트"
- 헤딩마다 붙는 장식 라벨(자간 넓은 대문자 소제목·아이콘 라벨)
- 헤드라인의 한 단어만 색칠하기
- 이모지를 구조 아이콘으로 쓰기
- 모든 요소에 호버 움직임·떠오름 효과
- 강조색을 네 곳 이상에 흩뿌리기
- 가운데 좁은 카드 하나에 화면 전체를 담기(넓은 화면의 2/3 가 비는 배치)

## ③ 찍고 보고 다듬기 (자가 점검 — 최대 2회)

```bash
bash "${CLAUDE_PLUGIN_ROOT}"/scripts/_internal/screen-shot.sh screens/<name>.html .specops/<FID>/shots/<name>
```

나온 `@1280.png`·`@390.png` 두 장을 Read 로 열어 아래 7줄을 대조하고, 어긋난 곳을 고친 뒤 다시 찍는다(최대 2회). `SCREEN-SHOT: SKIP` 이면 찍지 못했다고 사용자에게 적는다 — 확인한 척하지 않는다.

1. **위계** — 눈이 가장 먼저 가는 곳이 브리프 3번(주 액션·핵심 수치)인가
2. **빈 공간** — 1280 첫 화면에서 의미 없는 빈 영역이 1/3 을 넘지 않는가
3. **리듬** — 같은 관계의 간격이 같은가, 들쭉날쭉한 여백이 없는가
4. **정렬** — 표 숫자 우측, 라벨·입력 정렬, 버튼 높이가 맞는가
5. **대비** — 보조 글자가 배경에 묻히지 않는가, 상태가 색만으로 전달되지 않는가
6. **좁은 폭** — 390 에서 잘림·겹침·가로 스크롤(표 래퍼 밖)이 없는가
7. **빼기** — 금지 목록에 걸리는 장식이 있으면 하나 뺀다

사용자에게는 다듬은 결과와 스크린샷 경로를 함께 보여 준다.
